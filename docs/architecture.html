1요청 흐름

입구(채팅·폼) → 접수 → 에이전트 루프 → 계산 모듈. 숫자는 초록색 계산 계층에서만 만들어집니다.

화면API·검색접수 에이전트계산 (숫자의 유일한 출처)

5분석 포인트

숫자는 어디서 만들어지나

  • 금액·공수·할증·VAT는 quote.py 순수 함수에서만
  • 렌더러·검색·LLM은 숫자를 만들지 않음 → 견적서 숫자 = estimate() 결과를 테스트로 고정
  • 문서(modules.md)와 코드 상수가 다르면 테스트 실패

LLM 교체 지점 2곳

  • RulePlanner.next_action(state) → LLM tool-use 플래너
  • intake.extract(text) → LLM 조건 추출 (구조화만)
  • 두 곳 모두 금액 계산과 분리되어 있어 바꿔도 숫자는 그대로

실제 데이터 vs 가정값

  • 실제: cases.csv 입찰공고 8건 (약식 0.27~0.9억 / 전사 4.5~8.9억), KOSA 2026 임금
  • 가정: 단가표, 공수 계수, 할증률, 최대 8명, 서울대 기준 조건
  • 교수 수 확인 사례 1건 → 계수 보정 불가 → 모든 견적 review.required

하이브리드 검색의 현재 역할

  • 템플릿 재사용. 지금은 근거 문서 출처 표시용, 금액에 영향 없음
  • 필요해지는 시점: RFP 업로드(정확한 문구·숫자), 사례 수백 건 유사 검색(ISP/ISMP 약어), 공고번호 조회
  • 한국어 조사 문제(Postgres simple) → 측정 후 n-gram 도입
